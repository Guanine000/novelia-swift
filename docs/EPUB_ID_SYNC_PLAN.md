# 网络小说 EPUB 按小说和章节 ID 同步实施计划

状态：1.2.0 实现记录。已完成章节身份、目录核对、EPUB 更新及旧下载配置补齐；构建与分发状态以对应 Release 和构建记录为准，真实多设备体验仍需持续验证。以下原计划及历史实现记录保留追溯。

## 目标与范围

网络小说 EPUB 的阅读进度与书签按「书源 ID + 小说 ID + 源站章节 ID + 章内比例」定位，使同一小说不同 EPUB 版本共享状态。文件哈希继续用于下载校验、文件版本和排版缓存，不再作为已识别网络小说的唯一阅读状态身份。

用户明确限定：本轮只修改书库中属于“网络小说”来源的 EPUB。文库小说（包括文库下载与本地导入）保持现有文件哈希身份、进度、书签及同步规则；不得因共用模型或阅读器而迁移文库数据。已移动到文库的书也不因仍有 `sourceWebNovel` 自动加入迁移。本轮不扩展在线阅读的章节内同步，不改普通导入 EPUB/TXT 和未识别网络小说文件的哈希身份，不恢复 iCloud 方案。不同译源/语言模式共用小说和章节身份，章内比例为近似位置，不宣称不同正文精确逐字对齐。现有 WebDAV 手动取回新版功能保留，用于获取缺失章节。

## 实施前基线与已确认问题

- 本地最新测试包为 1.2.0（108），未提交、推送或公开发布；工作区包含107/108全部改动，后续必须保留。构建号不得复用，下一测试包至少109。
- `SyncedReadingPosition` 以 `epub:<hash>` 保存 spine 序号、章内比例、UTF-16偏移和兼容全书比例；`ReaderBookmark` 也使用哈希身份。
- 网站生成器使用 `Text/episode1.xhtml` 等序号路径，没有在资源路径中保存源站章节 ID。来源：AutoNovel `server/src/main/kotlin/infra/web/repository/makeEpub.kt`，已检查提交 7de140301bf5fdf36ccd9472e024bf5e8ad4161c。链接：https://github.com/auto-novel/auto-novel/blob/7de140301bf5fdf36ccd9472e024bf5e8ad4161c/server/src/main/kotlin/infra/web/repository/makeEpub.kt 。仅参考格式，独立 Swift 实现；上游 GPL-3.0。
- 因此108的唯一章节路径映射只能覆盖路径含义未变的情形，目录中间插入、删除或重排时存在错配风险，不能把 episode 序号称为稳定章节 ID。
- `Novel.chapters` 有章节 ID，但现有下载记录可能持有陈旧或不完整目录；不能把当前网站目录直接套到历史 EPUB，也不能仅凭相同标题认定章节身份。

## 预期行为

1. 两端 EPUB 版本不同，但都有目标章节：同步后按章节 ID 和章内比例恢复，不要求重新下载文件。
2. 旧版缺少目标章节：保留同步位置，提示「本机版本未包含该章节，请更新 EPUB」。打开旧书、临时显示首页或末章不产生新进度；只有用户实际阅读/主动定位才写入。
3. 缺失章节的书签保留并可删除，显示不可跳转及更新提示，不夹到最近章节或错误索引。
4. 章节插入、删除、重排不改变现有章节身份。相同章名不能互相替代。
5. 进度仍按最后修改时间合并，不采用最远进度；书签按稳定 UUID 和修改时间合并，包括删除墓碑。只打开/恢复不刷新修改时间。
6. 有效章节映射离线可用；网络失败不破坏原文件和历史状态。

## 网络小说读完后的更新界面（2026-10-29 新增需求，已纳入实现）

仅对当前网络小说来源的本机 EPUB 启用。文库、普通导入及在线阅读不增加此界面。

- **触发**：最后一章正文保持完整可读；到本机最后一页后继续向后翻，显示“已读完本机已下载章节”页面（两引擎的点按下一页和向后翻手势一致）。提供“返回阅读”，保留原末页位置；不能在刚进入最后一章时遮住正文，不为展示结束页新增虚假章节/阅读进度。
- **显示内容**：书名、已读完提示、“还有 N 章未下载”，主按钮“更新至最新章节”。可补充本机已下载章数及网站最新章数，必须区分网站可见章节与译文完成数量，不将未翻译章节误称为已下载正文。
- **数量来源**：通过既有 `NovelCatalogService` 请求该小说最新目录，按去重后的源站章节ID集合与本机可信映射中实际可用章节比对。中间缺章同样统计，不能只做最新总数减旧下载记录总数，也不能把目录分组/封面/导航页计为章节。此次查询仅获取目录，不自动下载正文或覆盖文件。
- **已下载旧书**：复用上述专项迁移/核验，针对当前文件确定章节ID；未核验或仅有部分可信映射时不展示猜测的精确缺章数，应显示“正在核对本机章节”或“暂无法确认未下载数量”，提供核对/重试入口，仍允许用户选择更新。不能因数量未知阻止旧书阅读或要求先全部重下。
- **查询状态**：首次展示时检查，显示加载态；离线/失败显示“暂时无法检查更新”及重试，不把失败显示成0章。重复展示可使用本次会话结果并允许刷新；结果带检查时间，更新后重新核验。后台/离开时取消无用请求，避免迟到响应覆盖新文件结果。
- **没有新章节**：明确显示“本机已包含网站当前全部章节”，不将其解释为正文/翻译一定没有修订；保留手动刷新/更新能力，按钮文案及结果如实区分新增章节和同内容。
- **更新动作**：点击“更新至最新章节”复用同一下载Store的整本EPUB更新事务，沿用现有译源/语言模式，不触发源站抓取或翻译；显示进度和取消，防止重复点击。网络/校验/写盘失败保留原书与阅读状态，提供重试，返回阅读随时可用。书籍删除/移动/替换后不能复活或覆盖新记录。
- **更新成功**：重新绑定并打开更新后的文件（旧容器/Readium导航器不得继续持有已删除旧文件），按稳定章节ID保留原末章位置，提供“继续阅读新章节”；仅在用户选择后跳到本机原末章之后实际新增章节，不因更新自动推进进度。若目录重排/缺章，沿用ID缺章处理，不按旧spine序号猜测。文件相同则告知无内容变化，不重置位置。
- **职责与接线**：阅读器仅报告已到末页/请求更新界面；目录查询和下载Store连接由App集成层注入，不在排版模型或View内创建具体API/WebDAV客户端。共用状态实例，网络小说来源显式控制入口；文库末页和翻页行为不变。
- **测试**：两引擎点按/手势到末页、返回末页、缺章集合计算（追加/中间缺章/重排/同名/重复ID/分组页）、旧书映射未知、0章、离线/失败/重试、重复点击/取消、更新失败/同内容、更新后文件重新打开及继续新增章节、并发删除/移动、文库不显示；真实服务器和用户原书另验。

## 阶段一：定义数据契约和可靠章节映射

- 为网络小说定义稳定阅读身份，使用 providerId/novelId 的无歧义编码；与现有 `web:` 在线阅读位置分开，避免在线章节序号记录冲掉 EPUB 章内位置。建议新命名空间 `webepub:`，具体编码以实现和测试统一。
- `SyncedReadingPosition` / `ReaderBookmark` 增加可选 `chapterID`，保留旧字段用于旧数据和本机显示；索引与全书比例不是跨版本身份。
- 下载记录增加可选版本化章节映射，至少含文件 SHA-256、包内资源路径到源站章节 ID 的对应关系、映射来源与可用性。与具体文件强绑定，禁止新映射套旧文件；映射随该版本书目同步（优先可选记录字段，不新增依赖）。
- 核验现有下载 API 是否能提供与生成文件同一快照的目录/版本。能取得同快照时优先使用；否则下载前后获取目录，结合实际 EPUB 结构/章节标题验证，仅在对应关系充分确定时建立映射。
- 下载前后目录一致只是降低竞态风险，不等于证明同一生成快照；若只能靠序号猜测，标记未映射并保留兼容路径，不能宣称实现可靠 ID 同步。重复标题、缺章、目录差异及历史文件不得静默强配。
- 具体 API 仍由 Domain 服务协议与 Root 集成注入，阅读器不直接创建客户端。不改写用户原始 EPUB。

阶段验收：合成目录/EPUB可证明映射绑定、插章重排、不重复章节 ID、目录变化拒绝错误映射；明确旧文件可迁移和不可迁移条件。

## 阶段二：统一进度和书签存储及迁移

- Core 提供章节 ID 与本机资源/索引转换，两个阅读引擎共用；不要维护各引擎独立的持久化真相。
- 已可靠映射的网络小说统一写稳定小说键、章节 ID、章内比例；UTF-16偏移或 Readium Locator仅作为同文件本机精度辅助，跨文件优先使用章内比例。
- 从当前文件旧哈希记录迁移时保留原时间，位置按时间合并。书签保留原 UUID，避免为每次文件更新复制新身份。
- 处理107/108产生的确定性复制书签：基于已有旧UUID与目标哈希派生规则建立可证明的关联，合并增删墓碑；无法证明关联的不按标题/位置盲目去重。
- 旧数据保留，迁移可重复执行、不刷新时间、不重复书签、不复活已删项；中断/写盘失败后可重试。
- 迁移仅使用可信的该文件目录快照；无法确认历史章节身份时保留旧状态并说明需要重新定位，不按最新目录强迁。

阶段验收：跨版本同章、不同正文比例、两端旧数据归并、新版较新状态保护、删除传播、迁移重试与失败保护。

## 已下载网络小说的专项迁移方案（必须实现）

此方案覆盖升级前已下载、没有新章节映射的网络小说，不能只支持未来新下载，也不能要求用户删除旧书或全部重新下载。

1. **筛选与保留**：只选当前网络小说来源的 EPUB，保留文件、原下载记录、旧哈希进度、书签UUID与删除墓碑；迁移状态持久化，禁止重复生成身份。文库来源直接排除。
2. **按每个本机文件建立映射**：先用本机旧下载记录内的目录快照、EPUB实际目录/章节资源和可验证的源站信息交叉核验。每台设备针对自己的旧文件处理，不能把另一设备或云端最新版映射套上来。记录映射绑定的文件hash及核验依据。
3. **分级处理**：有可信旧快照且对应关系充分确定的自动迁移；只能确认部分章节时，仅迁移可确认部分。当前目录仅可作核对线索，不能仅凭episode序号、章节数量或同名标题认定身份。旧快照过期/缺失、插章重排或同名冲突时保留未确认记录。
4. **无法自动确认的补救入口**：显示“需要确认章节对应”的状态，允许用户为当前阅读位置/书签选择源站章节，保存经确认的映射；支持之后补全并重试。无网络时继续按旧状态阅读，不阻塞打开。重新下载/取回新版只能是用户可选的补救，不能成为保留旧进度和书签的前提。
5. **迁移提交**：先生成并校验新状态，再原子提交/记录完成标记，保留原更新时间、UUID和墓碑；中断或写盘失败可重试，不删旧状态、不刷新时间、不覆盖较新的ID状态。107/108派生书签的可证明关联也要归并，避免同一书签升级后出现多份。
6. **双设备汇合**：手机和平板分别迁移各自已有版本，再按稳定小说/章节ID同步；取各自较新位置并合并书签增删，不以云端新EPUB的章节顺序解释本机旧进度。两端旧文件不同也应能处理，缺失章节按缺章规则保留。
7. **触发与性能**：优先首次打开/更新该书时按需迁移，提供可见的检查/重试入口；不在升级启动时同步阻塞扫描全部书籍，不静默批量重下，不因迁移失败报“已完成”。

专项验收：升级前已下载书无须重新下载即可在可信映射下迁移；无快照/错误快照/重复标题/部分可确认、离线、取消/崩溃重试、已有云端较新状态、已删除书签、107/108复制书签、两端不同旧版本均覆盖。文库小说的进度、书签、身份与同步行为回归保持原样。

## 阶段三：接入 Yuedu 与 Readium 及书库展示

- `LibraryReaderDestination` 仅对当前网络小说来源，经 `EPUBReaderHost` 显式传入小说身份和文件映射；文库来源不启用该分支，保留 `sourceWebNovel` 也不自动迁移。共用阅读器/模型新增字段不得改变文库行为，普通导入不凭书名匹配。
- 原生 `EPUBReaderModel` 读写 ID 位置；Readium 模型在 readingOrder 与原生 spine 之间按实际资源转换，不假设两者索引一致。
- Readium 本机 Locator不得遮蔽跨设备较新状态；映射不到章节时不能回退全书比例并误写新时间。
- 共用书签面板/按钮按章节 ID查询、添加、删除和跳转。显示排序使用当前文件章节顺序；不存在的章节显示缺失状态，保留删除能力。
- 书库继续阅读/最近阅读读取稳定状态；不同版本不沿用另一版本的全书百分比，优先显示章节信息。
- 打开后正常同步到来的新状态不能被打开/恢复回调覆盖；沿用明确的恢复与用户交互区分。

阶段验收：两引擎分别覆盖恢复、翻页保存、书签按钮/列表、缺失章节提示和不写回、同步后重开、引擎切换。

阶段验收：同小说不同文件hash可双向同步；一个缺章的旧版不覆盖新位置；书籍/映射版本并发变更、旧客户端重写、删除墓碑和断网重试均有明确结果。

## 111 补充实现

唯一标题/卷名先匹配，再用已确认的前后章与连续标题序列缩小歧义；只接受所有可行有序对应中相同的项，插删同名章仍歧义则不绑定。顺序交叉不推断，正文不批量请求。手动待确认列表显示候选序号/卷名/前后文，必要时并排预览，确认后继续下一条；保留完整目录兜底和显式更正。两引擎目录顶部“目录 / 图片 / 章节更新”为入口，原工具栏独立循环箭头移除，末页入口保留。没有书签的章节仍可能用于阅读进度和缺章计数，不能仅按书签有无跳过身份对应。

## 113 用户反馈修订
