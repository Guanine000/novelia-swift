# 性能基线与故障验收

[← 返回 README](../README.md) · [开发文档](../DEVELOPMENT.md) · [构建说明](BUILD.md)

## 证据范围

性能报告必须记录源码身份、运行环境、构建配置、样本规模、重复次数及原始结果。主机微基准、模拟器 Debug 基准、实体设备 Release 验收分别保存；测试通过只表示用例完成，不能据此宣称所有设备性能达标。

基线使用合成样本，不读取真实账号、凭据、个人书籍或生产 WebDAV。基准产物放在忽略的 `build/performance/` 或系统临时目录，不作为发布附件。

## 书库存储微基准

从仓库根目录运行：

```sh
python3 scripts/test_library_transactions.py --benchmark \
  --output build/performance/storage.json
```

该脚本直接编译生产书库 Store、记录模型、索引事务、文件复制及移动协调代码；UIKit 图片转换、EPUB 元数据和远端下载使用本地适配。它测量空书库、300 本和 3000 本索引的读取、编辑提交，以及 9 MiB 文件复制，每项重复五次。读取样本处于文件系统暖缓存中，不能当作手机冷启动成绩；主机文件复制也可能使用文件系统克隆，不能用其耗时推断物理介质吞吐或手机复制速度。

需要比较旧实现时显式指定一个保留旧同步索引实现的提交：

```sh
python3 scripts/test_library_transactions.py --benchmark \
  --baseline-ref '<旧实现提交>' \
  --output build/performance/storage-comparison.json
```

旧 Store 只替换类名、平台适配和存储目录，所有读写都指向临时合成数据。报告另包含注入 80 ms 存储延迟的对照：分别记录同步等待与异步写入期间的 MainActor 最大心跳间隔。这是受控慢存储实验，验证主执行域是否被阻塞，不能用其百分比代表真实设备速度提升。

## 模拟器实际 App 基准

先按开发文档编译独立验证 App，应用标识必须为 `cc.novelia.ios.architecture-validation`，然后运行：

```sh
python3 scripts/test_api_architecture_ui.py \
  --device '<模拟器 UDID>' \
  --app '<独立验证 Novelia.app 的绝对路径>' \
  --performance --library-count 300 --iterations 3 \
  --result-json build/performance/simulator-300.json
```

`--library-count` 支持 0、300、3000；重复次数支持 2–10。样本在计时前单独生成，测量应用启动、书库滚动的耗时／CPU／内存和滚动指标，以及启动后打开约 9 MiB TXT、内置 EPUB 样例至分页可操作。EPUB 样例含三章、图片、外部样式与注脚，默认使用 Yuedu；文件生成在计时前完成，不能代表所有 EPUB 排版。空书库跳过滚动测量；长 TXT 用例会在自己的测量前添加样本。

长 TXT 和样例 EPUB 指标包含启动、自动化交互与就绪等待，不是纯解析或纯排版耗时。报告保留源码哈希、版本、构建号、模拟器 ID、原始 xcresult 指标和测试目录。不得把这些 Debug／模拟器结果当作实体设备能耗或 Release 性能结论。

## 实体设备验收

使用包含当前源码的新构建，在主力设备和一台较慢的受支持设备上分别建立基线。记录设备型号、系统、构建、阅读引擎、样本大小、电量与温度条件；每轮使用相同样本和操作，并避免测量时同时构建项目。

| 场景 | 检查内容 |
|---|---|
| 空书库、300 本及更大书库 | 冷启动、首次可操作、来源筛选、搜索和连续滚动 |
| 普通／图片较多／长章节 EPUB | 首屏、连续翻页、跨章、目录、旋转及字号调整后的恢复 |
| 约 9 MiB TXT | 首次打开、搜索与取消、章节跳转、再次打开和进度恢复 |
| 导入、跨书库移动、编辑封面及批量删除 | 主线程卡顿、操作结果、失败提示与原文件保留 |
| 连续阅读至少 30 分钟 | CPU、内存变化、后台暂停、返回后恢复及异常耗电 |

使用 Xcode Instruments 的 CPU、内存和能耗分析工具保留记录。先依据这些设备的实测基线制定预算，再比较优化前后的中位数、较慢样本和主线程停顿。当前脚本不内置统一设备阈值，也不自动判定 1.0 合格。

## 故障与升级回归

```sh
python3 scripts/test_library_transactions.py
scripts/run_package_tests.sh '<模拟器名称或 UDID>'
```

真实书库 Store 回归覆盖旧格式缺字段、损坏索引保留与修复重读、编辑／删除写盘失败、跨库移动失败回滚及回滚失败提示、在途提交后追加操作、取消移动、复制与删除竞争。只在索引持久化成功后发布状态，文件清理随后执行；清理失败可能留下不可见的孤立文件，不能把它报告成原书数据丢失。

Core 同步回归覆盖未读取本地索引时阻止远端操作、远端已提交但本机删除失败后的重试，以及上传期间继续阅读的进度在下一次同步中补传。

真实 WebDAV 双设备仍须验收：书籍、书签、信息编辑、进度和统计往返；双端并发修改；断网、取消、缺失文件与重试；旧版本覆盖安装后的数据保留。合成后台或临时本地文件回归不能替代这一步。
